Skip new objects whose prerequisite the policy withholds and the target lacks, instead of throwing a missing-requirement error or emitting DDL that fails at apply. A user trigger on a reference-only `supabase_migrations.schema_migrations` (CLI-2300), pgsodium column defaults, views and security labels (CLI-2342), and views over a Wrappers foreign table (CLI-2178) are now reverted at plan time into `filteredDeltas` with their subtree and reported as `excluded-by-cascade` warnings in `plan.diagnostics` (blocking under `--strict-coverage`). Only new tables, columns, defaults, views, triggers, security labels and PERMISSIVE RLS policies are skipped this way. A stranded change to an existing object, or a new fact of any other kind (a constraint, a RESTRICTIVE RLS policy, a function, …), is refused with a plan-time error instead, because skipping it would leave the old definition, missing enforcement or wider access live, unless what is missing is its table or a column of its table this plan also skips. A new NOT NULL or domain-typed column on a table the target already has is skipped together with its default, since the `ADD COLUMN` that carries it cannot run on existing rows without one; an existing column keeps its other changes and only loses the default. A new partitioned table whose partition key column is skipped, or a new table whose replica identity index is skipped, is skipped with it. Prerequisites that exist on the target, are produced by the plan, or are platform-provisioned still plan as before. The Supabase system-extension, system-schema and system-role-owner exclusion rules now carry readable reason codes.

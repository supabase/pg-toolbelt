`schema export --profile supabase` now round-trips named-role default grants onto an auto-expose-ON baseline. Absence of `anon` (or another overlay grantee) is a `REVOKE ALL` on create, not a silent keep of the load environment's injectee. A desired ADP that is a subset of the dest injectee is wipe-then-grant (`REVOKE ALL` then `GRANT` the live set) so extra dest privileges do not linger. Overlay ADP files in the default by-object layout load before object files so dest auto-expose does not inject grants onto unmodeled identity sequences. Create-time ADP hygiene uses the resolved default owner when database-scope projection has pruned that owner edge, so a table that predated a schema ADP still gets `REVOKE ALL` in its own file (load order does not have to match history). Overlay hygiene on `supabasePolicy` DB-to-DB creates only REVOKEs overlay roles the apply target's extract already has (stock Postgres without `anon` is not a failed apply). Overlay tuples live on the policy (`assumedDefaultGrants`); the planner still has no platform role names of its own.

`schema export --profile supabase` now round-trips named-role default grants onto an auto-expose-ON baseline. Absence of `anon` (or another overlay grantee) is a `REVOKE ALL` on create, not a silent keep of the load environment's injectee. A desired ADP that is a subset of the dest injectee is wipe-then-grant (`REVOKE ALL` then `GRANT` the live set) so extra dest privileges do not linger. Overlay `REVOKE ALL` ADP is a dedicated wipe file in the default by-object layout, loaded after `CREATE SCHEMA` / roles and before object files and `_cluster/extensions/*`, so dest auto-expose does not inject grants onto unmodeled identity sequences or extension members. Positive ADP `GRANT`s stay at plan order so a predating identity sequence is not created under them. Global GRANT ADP is `_cluster/default_privileges.sql`, not mixed into `roles.sql`. Create-time ADP hygiene uses the resolved default owner when database-scope projection has pruned that owner edge, so a table that predated a schema ADP still gets `REVOKE ALL` in its own file (load order does not have to match history). Overlay hygiene on `supabasePolicy` DB-to-DB creates only REVOKEs overlay roles the apply target's extract already has (stock Postgres without `anon` is not a failed apply). Overlay tuples live on the policy (`assumedDefaultGrants`); the planner still has no platform role names of its own.
